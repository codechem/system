# Tab (`<cc-tab>`)

## Goal

Build `<cc-tab>` from the Figma "Tab" component set (file `K7Z7bb2IjqiyDjik5qjEoN`, node `337:2993`, opened from link node `373:15354`, which is the component set's documentation frame on the "Tab button" page). One tab item, in two types (Enclosed, Line) and two selected states, across five interaction states.

## Requirements

### From Figma

- Component set `Tab`, 20 variants: `Type` (Enclosed | Line) × `Selected` (True | False) × `State` (Enabled, Hovered, Pressed, Focused, Disabled).
- Every variant is 89 × 44 px (hugs its label: 24 px side padding, 8 px top and bottom padding, 16 px medium text, 28 px line height).
- Label text: Kumbh Sans Medium, `Text Size/body/md`, `Line Height/body/md`, `Typeface/typeface`.
- Corners: 4 px on the top two corners, 0 on the bottom.
- Enclosed, selected: 2 px inside stroke on top, left and right (no bottom), `Border/low-contrast`, label `Accent/light`.
- Enclosed, unselected: 2 px inside stroke on the bottom only, `Border/low-contrast`, label `Text/low-emphasis`.
- Line, selected: 3 px bottom stroke, `Accent/light`, label `Accent/light`.
- Line, unselected: 2 px bottom stroke, `Border/low-contrast`, label `Text/low-emphasis`.
- Hovered: background `Surface/surface-2`. Pressed: the same background with opacity 0.7. Disabled: opacity 0.4.
- Hovered and Pressed on a Line tab that is selected keep the accent underline.
- Focused: a focus ring 4 px outside the tab edge, 2 px wide, `Border/focus`, corner radius 8. Shown as an absolutely positioned child (`focus ring`).

### Expected behaviour (from the plan and WAI-ARIA)

- Plan, Wave D: "Tabs: full WAI-ARIA tabs pattern (arrow keys, automatic vs manual activation)." This build covers the single tab item. See *Left out*.
- The inner element is a native `<button>` with `role="tab"` and `aria-selected`, so it is keyboard operable (Enter and Space activate it). `role="tab"` is only valid inside a `role="tablist"`; the JSDoc says so, and the stories wrap every tab in one.
- Disabled: the native button is disabled, and host click listeners are blocked.
- Focus shows the shared focus style (`:focus-visible`, `2px solid var(--cc-border-focus)`).

## Steps taken

1. Read the component set with the `figma-inspect.md` read-only scripts (step A found the set, step B described its variants with bound variable names), took a screenshot, and read section 6 (Wave D) and section 8 (Definition of Done) of the plan.
2. Checked that every bound variable has a matching `--cc-*` token in `packages/tokens/dist/tokens.css`: `Border/low-contrast`, `Border/focus`, `Accent/light`, `Text/low-emphasis`, `Surface/surface-2`, `Typeface/typeface`, `Text Size/body/md`, `Line Height/body/md`, `Font Weight/medium`, `Padding/padding - 1`, `Padding/padding - 3`, `radius`.
3. Wrote `packages/components/src/tab/cc-tab.ts`:
   - Properties: `type` (`enclosed` | `line`, default `enclosed`), `selected` (default off), `disabled`, `aria-label`.
   - The Figma "Type" enum becomes `type`. The Figma "Selected" boolean defaults to True in Figma, but a tab defaults to unselected, so the element uses `selected` (default off), the same call made for `<cc-switch>`.
   - Per-side edges are drawn with `box-shadow: inset …` and a private `--_edge` variable. A border would shift the label by 2 px, while Figma's inside stroke does not move the content.
   - Focus uses `outline: 2px solid var(--cc-border-focus)` with `outline-offset: 4px`, which sits where Figma's ring does. See *Designer questions* for the corner radius.
   - `shadowRootOptions.delegatesFocus = true`; `click()` and host `aria-label` are forwarded; disabled host clicks are blocked.
4. Wrote `cc-tab.stories.ts`, following the link stories: `Default`, `Line`, `Selected`, `SelectedLine`, `Disabled`, and `AllVariants`, a grid over type × selected × disabled with the controls disabled.
5. Wrote `cc-tab.test.ts` (23 tests in Vitest Browser Mode, Chromium).
6. Registered the component: `src/index.ts` export, `package.json` `./tab.js` export (before `./custom-elements.json`), README "What's inside" row and "Project layout" folder.
7. Verified (see below), then wrote this doc and ran the code review.

## Left out

- **Tablist container.** Arrow-key movement, roving `tabindex` and automatic vs manual activation need a `<cc-tabs>` container, the same way `<cc-radio-group>` manages `<cc-radio>`. This build ships the single item. Plan status: `Done: <cc-tab>; tablist group (arrow keys, roving tabindex) not started`.
- **Pressed and Hovered forced states in stories.** They are CSS pseudo-states (`:hover`, `:active`, `:focus-visible`), so they are shown by interaction, not by a story arg.
- **Label slot icons.** The Figma set has no icon slot.

## Designer questions

1. **Focus ring corner radius.** The Figma focus ring has an 8 px radius, but the tab's own corners are 4 px at the top and 0 at the bottom. Using `outline` makes the ring follow the tab's 4 px radius, so the ring corners are tighter than Figma's. Is an 8 px ring intended?
2. **Enclosed selected stroke colour.** The selected Enclosed tab keeps the neutral `Border/low-contrast` stroke while its label is accent. The selected Line tab uses accent for both. Is the neutral outline intended?
3. **Selected default.** The component set's default variant is `Selected=True`. The element defaults to unselected; confirm that is the intended default for a tab.
