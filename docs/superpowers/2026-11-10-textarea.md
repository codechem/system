# Text area

**Date:** 2026-11-10
**Changes:** uncommitted in the working tree.

## Goal

Build `<cc-textarea>` from the Figma "Text area" component set (file `K7Z7bb2IjqiyDjik5qjEoN`, set `372:11450`). The linked node `373:15196` is the documentation frame ("Text Area"). The plan (Wave C) asks for a form-associated component with value, validity, `required`, `disabled` and form reset.

## Requirements

### From Figma

- **Properties:** `State` (Enabled, Hovered, Active/Focused, Pressed); booleans Show below supporting text (off), Show asterisk (on), Show label + icons (on), Show placeholder (on), Show icon information (on), Show input text (off); text properties Label, Placeholder text, Input text.
- **Layout:** 320px wide column, gap `gap-1` (8px): label row (24px, gap `gap-0-5`), text field (96px), supporting text (16px).
- **Label row:** `Label/large, semiBold` (16/24) in `Text/high-emphasis`, a `*` in `Alert/error/main`, and a 16px `info` icon in `Text/low-emphasis`.
- **Text field:** fill `Surface/surface-2`, radius `radius` (4px), padding `padding-1` / `padding-1-5` (8px / 12px), content area 296×80, native-looking resize grip in the bottom-right corner.
- **Text:** `Body text/medium` (16/28) regular; placeholder in `Text/low-emphasis`, input text in `Text/high-emphasis`.
- **Supporting text:** `Label/small` (12/16) in `Text/high-emphasis`.
- **States:**
  - Hovered: an extra `Surface/surface-highlight-transparent` fill on the field.
  - Active/Focused: 2px inside stroke `Border/focus`.
  - Pressed: the whole component at opacity 0.7, with the hover fill.

### Behaviour

- Form-associated: submits its value under `name`, resets to its initial value, is left out when disabled, is invalid while `required` and empty.
- A real `<textarea>` inside the shadow root, named by its `<label>`.
- `input` bubbles from the inner textarea; `change` is re-dispatched (it isn't composed).

## Steps taken

1. **Read Figma** (read-only `use_figma`), including the `.Icon information` and `Resize` sub-frames, and the screenshot as the visual target.
2. **API:** `<cc-textarea label placeholder value name supporting-text required disabled hide-info-icon aria-label>`.
   - **`label`, `placeholder`, `supporting-text` as attributes:** Figma's text properties. A part is rendered only when its text is set, which covers "Show label", "Show below supporting text" and "Show placeholder".
   - **`hide-info-icon`:** Figma's "Show icon information" is on by default, so it becomes an off switch.
   - **`required` drives the asterisk** instead of a separate switch: an asterisk on an optional field would mislead, and `required` is also what the form validity needs. See designer questions.
   - **"Input text" is the `value`.**
3. **Styles:** tokens only. The field is a `div` carrying the fill, padding, radius and stroke; the `<textarea>` is transparent and 80px high (`--cc-unit-10x`). The hover fill is a `background-image` layer over `surface-2`. The focus stroke is `box-shadow: inset 0 0 0 2px` (Figma's inside stroke) on `:focus-within`. The width is 320px (no token), capped by `max-inline-size: 100%`.
4. **Form behaviour:** `formAssociated`, `setFormValue` and validity (`valueMissing`, anchored to the inner textarea) in `updated()`, `formResetCallback` back to the `value` attribute, `live()` binding of the value, `delegatesFocus`, `click()` forwarding, `aria-label` forwarding.
5. **Disabled:** opacity 0.4, `cursor: not-allowed`, native `disabled` on the textarea, and a host click listener that blocks author listeners.
6. **Stories:** Default, WithSupportingText, WithValue, Disabled, AllVariants.
7. **Tests:** `cc-textarea.test.ts`, 21 tests at first (26 after the review).
8. **Registered** in `src/index.ts`, the `exports` (`./textarea.js`) and the README.

## Verification

- `tsc` is clean, `vitest` passes 131/131 (21 for the textarea, before the review), `npm run build` succeeds.
- **Storybook against the Figma screenshot:** layout, spacing, label row, resize grip, hover fill and Tab focus stroke match.

## Left out

- **Pressed state:** `:active` on a text field is true during every click and drag-selection, so dimming it to 0.7 would flicker while the user selects text. Not implemented, see designer questions.
- **`readonly`, `maxlength`, `rows`, `autocomplete`, error state:** Figma defines none of them.
- **Auto-grow:** the field is a fixed 80px with a vertical resize grip, like Figma.
- **Custom resize grip:** the native one is used (visually close to Figma's).
- **Click on the label row focusing the field:** works through `<label for>`.
- **Default slot as initial text, JSDoc on `disabled`, axe checks, visual snapshot test, Code Connect, changeset:** not done here (Definition of Done items for the whole library, same as the other components).
- **Shared form-control controller:** not built yet (plan, Wave C); this is the form logic of `cc-checkbox` adapted for text.

## Designer questions

- **Pressed:** is a dimmed text area intended? A text field is "pressed" while the user selects text; consider dropping this state.
- **Hover fill:** the paint already has 50% opacity and the variable (`gray-600-opacity-50`) is 50% too, so Figma renders ~25%. The code uses the variable once (50%).
- **Info icon:** what does it do (tooltip? help link)? It is decorative for now and visible by default, which is odd on a field with no help.
- **Asterisk:** shown by default in Figma, but only meaningful on required fields. Is "asterisk = `required`" right?
- **No error or invalid state** is designed for the field or its supporting text.

## Review

Reviewed with `superpowers:requesting-code-review` by a separate reviewer agent, in a scratch clone with throwaway probes.

**Verdict:** no critical issues; four important form gaps, fixed.

**What the reviewer confirmed:** required validity, anchored `setValidity`, clearing it when `required` is turned off, reset through `live()`, newlines in submitted data, accessible name from `label` and `aria-label` (asterisk and icon don't leak), `aria-describedby`, registration, tokens-only styles, `delegatesFocus`, `click()` forwarding, the disabled click blocker and `change` re-dispatch. It declined to judge pixel match, screen readers, axe, Code Connect and the build.

| Severity | Finding | Fix or reason left |
|---|---|---|
| Important | A disabled `<fieldset>` didn't disable the inner textarea | `formDisabledCallback` into a private state, used for the attribute, the styles, the click blocker and validity; test |
| Important | No `formStateRestoreCallback` | Added; test |
| Important | No validity API on the element | `validity`, `validationMessage`, `willValidate`, `checkValidity()`, `reportValidity()`, `form`, `labels` pass through to `ElementInternals`; test |
| Important | External `<label for>` didn't name the field | The inner textarea gets `ariaLabelledByElements` from `labels` when there is no own label; test reads Chrome's accessibility tree (Playwright's role query ignores element reflection) |
| Minor | `formResetCallback` used `textContent` that is never rendered | Removed |
| Minor | A value set only through the property resets to `""` | Documented in the `value` JSDoc ("the attribute is the initial value", like `defaultValue`) |
| Minor | `not-allowed` cursor missing on the field padding | Set on `.root`, `.field` and the textarea |
| Minor | No JSDoc on properties | Added for the public ones |
| Minor | Test gaps (info icon visible, 96px field without label, fieldset, restore, validity, external label) | Tests added. Left: the weak "no hover when disabled" test (it checks the style, which the disabled textarea doesn't change) |
| Minor | No invalid state / `aria-invalid` | Already a designer question |
| Minor | axe, visual snapshot, changeset, `custom-elements.json` | Not part of this component's scope; see Left out |

**After the fixes:** `tsc` is clean, `vitest` passes 136/136 (26 for the textarea), and `npm run build` succeeds. A first fix attempt failed two new tests (a `setValidity` call with an empty message while disabled, and the label name); both are covered above.
