# Checkbox component

**Date:** 2026-11-09
**Base:** `8a67ae6`. Changes are uncommitted in the working tree.

## Goal

Build `<cc-checkbox>` from the Figma "Checkbox" component set (file `K7Z7bb2IjqiyDjik5qjEoN`, node `373:15965`). The linked node `373:15876` is the documentation frame.

## Requirements

### From Figma

- **Properties:** Type (Large, Medium), Selected (True, False), State (Enabled, Hovered, Pressed, Focused, Disabled). 20 variants. No label.
- **Box size:** Large is 40×40 with a 24px icon (`icon-md`). Medium is 32×32 with a 20px icon (`icon-sm`). The icon is centred.
- **Icons:** Material `check_box` (selected) and `check_box_outline_blank` (not selected).
- **Colours:**

  | | Enabled | Hovered | Pressed |
  |---|---|---|---|
  | Not selected | `Border/medium-contrast` | `Border/low-contrast` | as Hovered, opacity 0.7 |
  | Selected | `Accent/light` | `Accent/dark` | as Hovered, opacity 0.7 |

  Disabled is opacity 0.4.
- **Focused:** a 22×22 rounded rect inside the 24px icon frame, with a 2px `Border/focus` stroke drawn outside it. The ring sits 2px outside the box shape at Large and about 1.7px at Medium.

### Behaviour (not in Figma, expected of a checkbox)

- It works like a native checkbox: click, the Space key, a clickable label, and screen readers announce it as a checkbox.
- It takes part in forms: `name`/`value` are submitted only when checked, and form reset restores the initial state.
- It fires `change` and `input` events.

## Steps taken

1. **Found the component set.** The linked node was the documentation frame, so I searched the page for the `Checkbox` component set. Then I read the variants' sizes, fills, opacity, bound variables and vector paths with `use_figma` (read-only).
2. **Wrote `cc-checkbox.ts`.**
   - **Structure:** a native `<input type="checkbox">`, transparent and covering the box, inside a shadow `<label>` with the default slot as the label text. The browser handles keyboard, focus, label clicks and the checkbox role.
   - **Form association:** form-associated with `ElementInternals`. `setFormValue` runs after every update. `formResetCallback` restores the `checked` attribute. `checked` is not reflected, so the attribute keeps meaning "initially checked", as in native HTML.
   - **Events:** `checked` syncs on the inner `input` event, so listeners already see the new value. `change` is not composed, so it doesn't cross the shadow boundary and is re-dispatched from the host. `input` is composed and reaches the host on its own.
   - **`aria-label`:** an `aria-label` set on the host is forwarded to the inner input, so a checkbox without text still has a name.
   - **Focus:** `delegatesFocus` sends `el.focus()` to the input, and `click()` forwards to it.
   - **Icons:** the paths come from Figma and are inlined as Lit `svg` templates (the same convention as `cc-alert`), with `fill-rule="evenodd"` for the cut-outs.
   - **Focus ring:** an SVG `rect` over the full viewBox with a centred, non-scaling 2px stroke. That gives the same outer and inner edges as Figma's outside stroke: exact at Large, and about 0.2px off at Medium. `rx="3.44"` is Figma's 2.44 radius plus half the stroke. It is shown on `input:focus-visible`.
   - **Sizes and colours:** use `--cc-unit-4x`/`5x`, `--cc-icon-sm`/`md`, `--cc-border-*`, `--cc-accent-*` and `--cc-border-focus`.
   - **Size naming:** the attribute is `size="medium|large"`, defaulting to `medium`. Figma's "Type" became `size`, matching the other components.
3. **Stories:** Default, Checked, Disabled, WithoutLabel (with `aria-label`), and AllVariants.
4. **Tests:** `cc-checkbox.test.ts`, 15 tests:
   - defaults;
   - click, label-text click and keyboard toggling;
   - state already updated during `input`;
   - inner input kept in sync when a listener reverts the change;
   - disabled (programmatic and user click);
   - the accessible name from text and from `aria-label`;
   - the Figma colours;
   - both sizes;
   - the form value, leaving a disabled checkbox out of the form data, and form reset.
5. **Registered it** in `src/index.ts`, `package.json` `exports` (`./checkbox.js`) and the README.
6. **Kept Lit's `live()` directive** on `.checked`. Lit compares against the last value it rendered, not the input's current state. Without `live()`, a listener that sets `checked` back to its previous value would leave the inner input showing the opposite state. `live` is in `optimizeDeps.include` in `vitest.config.ts`, so Vite doesn't reload mid-run when it first sees it.

## Left out

- **Indeterminate state, `required` and validation messages:** not in Figma. Add them when a design needs them.
- **Disabling through a `<fieldset disabled>`** (`formDisabledCallback`): `cc-button` doesn't handle it either.
- **Label typography:** Figma has no label, so it uses the `label-m` regular text style in `text-high-emphasis`.
