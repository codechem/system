# Chip

**Date:** 2026-11-10
**Changes:** uncommitted in the working tree.

## Goal

Build `<cc-chip>` from the Figma "Chip" page (file `K7Z7bb2IjqiyDjik5qjEoN`). The linked node `876:4649` is the documentation frame. The page holds two component sets, both covered by one element (decided with the user):

- **Filter Chip** (`627:16566`, 96 variants): a toggle, optional leading and trailing icon.
- **Input Chip** (`688:6403`, 144 variants): optional leading icon or avatar, optional close button.

The plan (Wave A) says: "Chip: if removable or selectable, it gains interactive behavior; scope carefully."

## Requirements

### From Figma

- **Variant properties:** `Style` (Outlined, Filled), `State` (Enabled, Hovered, Focused, Dragged, Pressed, Disabled), `Selected` (False, True). Filter: `Configuration` (Icon + Label, Label Only), `Show Trailing Icon` (off by default). Input: `Configuration` (Label Only, Icon + Label, Avatar + Label), `Show Close Button` (off by default). Text: `Label`; instance swaps for the icons.
- **Label:** `Label/medium` (14/20, regular), `Text/medium-emphasis`, selected `Accent/contrast`.
- **Radius:** `radius` (4px); the input chip with an avatar is pill-shaped (`round`).
- **Icons:** 20px (`icon-sm`). Filter, selected: a `check` replaces the leading icon, also on a label-only chip.
- **Filter chip, padding** (all 8 top and bottom, gap `gap-1`): left 16, or 8 with a leading icon or check; right 16, or 8 with a trailing icon. Height 36.
- **Input chip, padding** (4 top and bottom, gap 8): left 12, 8 with an icon, 4 with an avatar; right 12 without a close button, 8 with it. Height 28. The close button is 20×20, square (round with an avatar).
- **Fills:**

| | Outlined | Filled |
|---|---|---|
| Filter | no fill, stroke `Border/medium-contrast` 1px inside | `Surface/surface-2` |
| Input | same | `Surface/surface-highlight` |
| Selected, outlined | `Accent/transparent` at 60%, stroke `Accent/light` | |
| Selected, filled | `Accent/dark`, stroke `Accent/light` | |

- **States:**
  - Hovered: filter outlined `surface-highlight-transparent` at 50%; filter filled `surface-highlight`; input gets a `transparent-highlight-2` overlay; selected outlined adds the same overlay; selected filled is `Accent/main`.
  - Pressed: the hover look at opacity 0.7.
  - Disabled: opacity 0.4.
  - Focused: filter, a 2px `Border/focus` ring 4px outside the chip. Input, a `transparent-highlight-3` fill and no ring.
  - Dragged: fill `surface-shade`.

### Behaviour

- The chip body is a toggle button (`aria-pressed`); a click toggles `selected` and fires `change`.
- An input chip with `removable` has a separate close button named "Remove <label>"; it fires `remove`. Delete or Backspace on the focused chip does the same.
- Disabled: no toggle, no events.

## Steps taken

1. **Read Figma** (read-only `use_figma`): property definitions of both sets, 72 filter variants and 24 + 16 input variants with bound variable names, padding per configuration, the screenshots of both sets.
2. **API:** `<cc-chip type="filter|input" variant="outlined|filled" selected disabled removable>` with slots default (label), `leading`, `trailing`, `avatar`.
   - **`type`:** Figma's "Variant" kind (filter or input). **`variant`:** Figma's "Style".
   - **`removable`:** "Show Close Button" is off by default, so it is a plain on switch. Ignored for filter chips.
   - **Icons and avatar as slots:** `leading`, `trailing` (filter only), `avatar` (input only). A slotchange handler reads the light DOM to switch the padding and the pill shape.
3. **Structure:** `.chip` (visual container, `part="chip"`) holds the native `<button class="body">` and, for removable input chips, a sibling `<button class="close">`. The buttons are siblings because a button cannot contain another. The focus ring, hover fill and pressed dimming are on `.chip` through `:has(.body:focus-visible)` and `:has(.body:active)`.
4. **Styles:** tokens only (`--_*` layer on `:host`, switched per `type`, `variant` and `selected`). The chip height follows from the padding (8 or 4) and the 20px line, as in Figma, since no 36px token exists. Highlight tokens already carry their alpha. Selected rules come after the input rules because `:host([type='input'][variant='filled'])` has the same specificity as `:host([selected][variant='filled'])`.
5. **Behaviour:** `delegatesFocus`, `click()` forwarded to the body, `aria-label` forwarded to the body, a host click listener that blocks clicks when disabled. The close button name follows the label text (slotchange).
6. **Stories:** Filter, FilterSelected, FilterWithIcons, Input, InputWithAvatar, Disabled, AllVariants (filter and input grids, both styles, unselected and selected).
7. **Tests:** `cc-chip.test.ts`, 48 tests (36 first, 12 added after the review).
8. **Registered** in `src/index.ts`, the `exports` (`./chip.js`) and the README.

## Verification

- `tsc` is clean, `vitest` passes 229/229 (48 for the chip), `npm run build` succeeds.
- **Sizes:** the tests measure the space around the label (32, 52, 72 for filter; 24, 48, 72, 68 for input) and the 36 and 28px heights, so they don't depend on the test browser's font. The label itself is 34.3px in the test browser against 36 in Figma, only a font difference.
- **Storybook against the Figma screenshots:** all rows of the filter and input grids, the check on a selected filter chip, the avatar pill, the close button, the disabled dimming, the hover fill (filled chip) and the Tab focus ring match.

## Left out

- **Dragged state:** no drag-and-drop in the library; the `surface-shade` fill is not implemented.
- **Form participation:** a chip is not a form control; use `selected` and `change`.
- **Avatar component:** `Avatar` is "Not started" in the plan; the `avatar` slot takes any element sized 20px and rounded (an `<img>` in the stories). It becomes a `<cc-avatar>` slot later.
- **Chip groups** (roving tabindex, single or multiple selection): not in Figma; each chip is its own tab stop.
- **Localised "Remove" label:** English only.
- **`custom-elements.json`, axe checks, visual snapshot, Code Connect, changeset:** Definition of Done items for the whole library, not done here.

## Designer questions

- **Focus differs between the sets:** the filter chip has a 2px ring outside, the input chip has a lighter fill and no ring. The code shows the ring on both (shared focus style) and adds the input fill.
- **Hover fills differ between the sets:** filter outlined uses `surface-highlight-transparent` at 50%, input outlined a white 8% overlay; filter filled hover is `surface-highlight`, input filled hover adds an 8% overlay on `surface-highlight`. Intended?
- **Filled fill differs:** filter filled is `surface-2`, input filled is `surface-highlight`.
- **Selected input chips:** is "Selected" for an input chip a toggle? The code toggles it on click like the filter chip, and `aria-pressed` reflects it.
- **Input chip with an icon but no close button:** not designed; the code uses 8px left and 12px right padding.
- **Pressed filter chip:** the pressed states of the filled selected chip lose the hover fill in some variants (`Accent/dark` instead of `Accent/main`); the code uses the hover fill for pressed.
- **Dragged state:** is it needed in code?

## Review

Reviewed with `superpowers:requesting-code-review` by a separate reviewer agent, in a scratch copy with throwaway probes (28 mutations).

**Verdict:** no Critical issues; two Important, seven Minor. Both Important and the cheap Minor ones are fixed.

**What the reviewer confirmed:** the house pattern is followed (`--_*` layer, `:host([hidden])`, `delegatesFocus`, `click()` and `aria-label` forwarding, disabled host click listener, focus, pressed and disabled styles like `cc-button`); the CSS ordering claim holds (selected rules override the input rules); hover fills resolve correctly because the highlight tokens carry their alpha; padding totals and the 36 and 28px heights match the requirements; toggling by click, Space and Enter fires `change` once; the close button does not toggle the chip and is disabled with it; slot content removed later clears the padding; registration is correct.

| Severity | Finding | Fix or reason left |
|---|---|---|
| Important | The close button name included ligature text of slotted icons ("Remove homeLabel") because `labelText` used `textContent` | The label now comes from the default slot's assigned nodes only; tests with icons that have no `aria-hidden` |
| Important | Editing a text node in place (`textNode.data = ...`) left the close button name stale | A `MutationObserver` (characterData, childList, subtree) re-runs the sync; test |
| Minor | Hover fill applied on a disabled chip | Hover rule is now `:host(:not([disabled]))`; test |
| Minor | Delete and Backspace fired on key repeat and with modifiers | Ignored with repeat, Cmd, Ctrl, Alt or Shift; tests. Delete from the close button is not handled on purpose: Enter and Space already activate it |
| Minor | `trailing` and `avatar` slots rendered for both types, so a trailing icon on an input chip was cramped | `trailing` renders only on filter chips, `avatar` only on input chips; test |
| Minor | `remove` carries no info and the chip does not remove itself | `@fires` says the chip does not remove itself; matches `cc-list-item` |
| Minor | Input chip focus differs from Figma (ring plus fill, Figma has fill only) | Left on purpose (shared focus style, DoD requires a visible ring); under designer questions |
| Minor | Raw `2px` and `4px` in the focus outline | Left: same as `cc-button`, no token exists |
| Minor | A selected input chip shows no check | Left: Figma shows the check only on filter chips; `aria-pressed` and the fill show the state |

**Mutation testing:** the tests caught 12 of 28 mutations at first. The 16 survivors were `aria-hidden` on the icon wrappers (4), `preventDefault` in the disabled listener, pressed opacity, input focus fill, hover overlay, selected-outlined tint, `:host([hidden])`, close hover and focus outline, `bubbles` on `change` and `remove` (2), and the right padding of an icon chip without a close button. Tests were added for all of them except close hover, close focus outline and the icon-chip right padding (a value Figma doesn't define).

**Declined by the reviewer:** screen readers, pixel match to Figma, axe, other browsers, the dragged state, reduced motion (no animations), Storybook rendering, the HTML and React sandboxes, and the designer questions.

**After the fixes:** `tsc` is clean, `vitest` passes 229/229 (48 for the chip), `npm run build` succeeds.
