# cc-avatar

## Goal

Build `<cc-avatar>` from the Figma "Avatar" component set in the CC Design System (file `K7Z7bb2IjqiyDjik5qjEoN`), the last open Wave A item after Link, Badge, Chip and Alert.

Source link: `figma.com/design/K7Z7bb2IjqiyDjik5qjEoN/...?node-id=373-15601`. That node is the Avatar documentation frame on the page "Avatar". The component set is node `372:8644`, with 12 variants.

## Requirements

### From Figma

- **Size**: Large (48px), Medium (40px), Small (20px). The Figma default is Large, but the house rule is that the default is `medium` when it exists, so the default here is `medium`.
- **Fill**: Icon or Image. Icon shows the Material Icons Round `person` glyph on a `Surface/surface-highlight` circle. Image fills the circle with a photo.
- **Notification Badge**: off by default. When on, a green `Status/green/main` badge sits flush with the top-right corner, with a 3px outside stroke in `background`.
  - Large: 16px badge with a number (`Label/extra small`, 12px, bold, `Status/green/contrast`). The code uses `--cc-text-size-label-s` (12px); no `label-xs` size token exists.
  - Medium and small: 6px dot.
- Geometry (measured from the Figma instances):
  - Icon sizes: Large 32px, Medium 24px, Small 16px. Icons are centred.
  - Badge positions: x=32 (Large), x=34 (Medium), x=14 (Small), all at y=0. The badge is absolutely positioned at top right.

### Expected behaviour

- Non-interactive. No keyboard or focus behaviour.
- Named for assistive technology: the host is `role="img"` with `aria-label` from `alt` (default "Avatar"). The icon ligature is not part of the name.
- Image avatars use `src`. Without `src`, the person icon is shown.

## Steps taken

   - Icons use `iconStyles` and the Material Icons Round font, with `aria-hidden`.
4. Wrote `cc-avatar.stories.ts` (Icon, Image, WithCount, WithDot, AllVariants) and `cc-avatar.test.ts` (18 tests).
5. Registered the component: `src/index.ts`, `package.json` exports (`./avatar.js`, before `./custom-elements.json`), and the README (components row and project layout).
6. Ran the verification suite (below).
7. Visual check in Storybook against the Figma screenshot (see Verification).

## Left out

- **Hover, focus, pressed and disabled states**: the Figma set has none. The avatar is not interactive.
- **Image sizing from Figma**: the Image variant in Figma has a placeholder image fill, not a real photo. The story uses an inline SVG placeholder.
- **Badge colour options**: Figma only has green. Other colours are not exposed.
- **Badge count for screen readers**: the host is `role="img"`, so children, including the Large badge count, are not announced. See Designer questions.
- **Decorative avatars**: `alt=""` is treated as "no name" and the host is named "Avatar". Figma has no decorative case, so there is no `role="presentation"` path. Pass a real `alt` when the name is known.
- **Broken image fallback**: if `src` fails to load, the broken image shows. There is no fallback to the person icon.
- **Two-digit badge growth**: the Large badge grows horizontally for counts like "12" or "99+". Figma only shows "1", so the growth is an extrapolation.

## Designer questions

1. **Person icon colour**: the icon's fill in Figma is a hard-coded `SOLID` colour, not a bound variable. I used `--cc-text-medium-emphasis` (gray-300), which looks right in the screenshot. Please confirm the intended token.
2. **Fill is Image without a photo**: the Image variant in Figma is just a frame with an image fill. The code shows an image when `src` is set and falls back to the person icon otherwise. Is that the intended behaviour?
3. **Large badge count**: the Figma Large badge shows the number "1". Should a count be part of the component API? Currently it is a slot, and the count is not announced by screen readers. A possible fix is to expose it through the host's accessible name.
4. **Badge colour**: all Figma badges are green. Should there be a colour property for future use, or stay fixed?
