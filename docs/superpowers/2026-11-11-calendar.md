# cc-calendar: Calendar date picker

## Goal

Build `<cc-calendar>`, a single-date calendar, from the Figma "Calendar date picker" component (node `1118:162`, file `K7Z7bb2IjqiyDjik5qjEoN`, page "Calendar component"). The plan (section 6, Wave E) says to ship single-date selection first.

## Requirements

From Figma (`1118:162`, 308×392, surface-2, 16px padding, 16px gap):

- Header row, then a 7-column day grid (Sunday first) with weekday labels, then a divider and a footer.
- Day cells are 36×36 with a 4px gap. Date cells: default and hover use an 8px radius, selected uses a 4px radius with the accent fill.
- Hover fill is `Surface/surface-highlight-transparent`. Selected fill is `Accent/main`.
- Footer: a secondary text button "Cancel" and a filled primary button "Done", right-aligned with a 16px gap.
- The grid has five week rows in the Figma sample.

Expected behaviour (from the plan and WAI-ARIA grid pattern):

- Locale-aware month, weekday and date labels (`Intl.DateTimeFormat`); Sunday is the first day.
- Arrow keys move by day and week, Home/End go to the week edges, PageUp/PageDown move by month. Enter and Space select.
- `min` and `max` limit selectable dates; unavailable dates stay focusable with `aria-disabled`.
- Picking a date fires `input`. Done commits it to `value` and fires `change`. Cancel drops the pending pick.
- Form-associated: `value` is the submitted value, and form reset clears it.

## Steps taken

1. Read the component set on the linked page with read-only `use_figma` calls. The linked node is the whole "Calendar component" page; the user chose `Calendar date picker`.
2. Read `.Day component` (`Mon`-style header text, `Text/low-emphasis`), `.Date component` (Default, Hover, Selected with fills and radii), the Filter Chip, the Month dropdown and the buttons.
3. Mapped Figma variable names to tokens. All colour, spacing, radius, typography and icon tokens exist in `tokens.css`. Two values have no token: the 36px cell size (raw px allowed) and the 15px weekday label (see Designer questions).
4. Built `packages/components/src/calendar/cc-calendar.ts` following the checkbox and button conventions: `formAssociated`, `ElementInternals`, `willUpdate` to sync the draft from `value`, `repeat` for keyed rows and cells, `aria-disabled` for unavailable dates.
5. Reused the existing `<cc-button>` for Cancel and Done rather than writing new buttons.
6. Wrote `cc-calendar.stories.ts` (Default, NoSelection, WithLimits, Disabled, AllVariants) and `cc-calendar.test.ts` (14 tests at first, 19 after the review).
7. Added `repeat` to `optimizeDeps.include` in `packages/components/vitest.config.ts`. Without it Vite reloaded the test run.
8. Registered the element: `src/index.ts` export, `package.json` `./calendar.js` entry before `./custom-elements.json`, README components row and project layout.

## Left out

- **Month dropdown and year chip** (Figma's Filters row). Their components are not built: the Month dropdown needs the `.Month Component` set (Figma's Closed/Opened states) and the year chip needs a decision about the Filter Chip's behaviour. The header uses prev/next buttons instead, which Figma does not draw. **Update 2026-11-12:** the dropdowns now exist, see [2026-11-12-calendar-month-year-dropdowns.md](2026-11-12-calendar-month-year-dropdowns.md).
- **Range selection** and **multiple months** (plan: "ship single-date selection first").
- **Drop shadows** (two shadows, radius 40 and 16). No shadow token exists in `tokens.css`, so none is applied.
- **Today marker**, not in Figma.
- **Keyboard keys beyond the grid pattern** such as Shift+PageUp for years.
- **Date input or popover**. The plan treats the input-plus-popover picker as a separate item.

## Designer questions

1. The Figma header is a Month dropdown and a year chip. Do you want that dropdown and chip in v1, or prev/next arrows like the build? The build uses arrows.
2. Figma's selected date has a 4px radius, while the default and hover states have 8px. The build follows that, which looks inconsistent in a grid. Is the 4px radius intended?
3. Weekday labels are 15px in Figma, with no matching token (nearest is `label-m`, 14px). The build uses `label-m`.
4. Figma's drop shadows (radius 40 and 16) have no token. Is a shadow token planned?
5. Figma shows days from the neighbouring months (for example 30 and 31 before November) in the same colour as the current month. The build dims them with `Text/low-emphasis` and makes them selectable, which moves the view to their month. Is that acceptable?
6. Figma shows five week rows. The build adds a sixth row when a month needs one, which changes the height. Should it always reserve six rows?
7. Figma has no disabled, min or max date state. The build uses opacity 0.4 for unavailable dates, the shared disabled style.

## Review

**Verdict:** Approve with fixes. The keyboard model, month rollover, time-zone handling and the Done/Cancel flow were confirmed correct. The findings below were fixed; the rest are accepted with reasons.

**Confirmed by the reviewer:** `tsc` clean; full suite passing at the time; throwaway browser probes for arrows across month and year boundaries, Home/End on Sunday and Saturday, PageUp/PageDown with day clamping, Space and Enter, the outside-day click, form reset, disabled FormData, focus outline, and time zones (Pacific/Kiritimati and America/Adak). Twelve single mutations were run against the test file: 10 were caught, 2 survived (host click guard, focus outline). Both gaps now have tests.

| Severity | Finding | Fix or reason left |
|---|---|---|
| Important | Form reset with a pending pick kept the pick, so a later Done committed it | Fixed: `formResetCallback` clears `draft`. Test: "clears a pending pick on form reset" |
| Important | No constraint validation: `required` missing, and `min`/`max` not enforced by the form | Fixed: `required` property; `setValidity` reports `valueMissing` and `rangeUnderflow`/`rangeOverflow`. Test: "is invalid when required and empty..." |
| Important | Disabled calendar dimmed twice (group and cell at 0.4, effective 0.16); axe reported colour-contrast nodes | Fixed: opacity applied once per group when disabled; per-cell dimming only for unavailable dates on an enabled calendar |
| Important | Disabled calendar still tabbable; arrows moved focus while disabled | Fixed: date buttons use native `disabled` while the calendar is disabled. Test asserts `disabled` on day buttons |
| Important | Focus dropped to `<body>` after an outside-day pick switched the month | Fixed: `select()` refocuses the picked day after the update. Test: "keeps focus on the picked day..." |
| Important | axe `label-content-name-mismatch` on the two nav buttons (visible ligature text not in the name) | Fixed: chevrons are drawn with icon-font codepoints in CSS, so no visible text is in the buttons. Not re-run through axe after the change: the throwaway axe probe was deleted. Verified by tests and Storybook only |
| Important | Test gap: host click guard not tested (mutation survived) | Fixed. Test: "blocks host-level clicks when disabled" |
| Important | Test gap: focus-visible outline not tested (mutation survived) | Fixed. Test: "shows a visible focus ring on the focused day" |
| Minor | `fieldset disabled` ignored | Fixed: `formDisabledCallback` |
| Minor | Day drifts across months: Jan 31 + two PageDown gives Mar 29, not Mar 31 | Accepted. The WAI-ARIA grid pattern does not require the anchor day to be kept |
| Minor | Raw `2px` for the focus outline and divider | Accepted. Existing components use the same raw width (pagination, alert) |

**Results after the fixes:** `tsc --noEmit` exit 0. `vitest run calendar` 19 of 19. Full `vitest run` 20 files, 446 tests, all passing. `npm run build` exit 0. The two mutations that survived before are now covered by tests; the other mutations were not re-run after the fixes.
