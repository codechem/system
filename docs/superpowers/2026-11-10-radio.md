# Radio button and radio group

**Date:** 2026-11-10
**Changes:** uncommitted in the working tree.

## Goal

Build `<cc-radio>` from the Figma "Radio button" component set (file `K7Z7bb2IjqiyDjik5qjEoN`, set `370:1622`), plus the `<cc-radio-group>` the plan asks for (section 6, Wave C: "Radio buttons need a group element"). The linked node `513:2384` is the documentation frame.

## Requirements

### From Figma

- **Properties:** State (Enabled, Hovered, Pressed, Focused, Disabled) × Selected (True, False). One size, no label, no group.
- **Size:** a 40px box (`--cc-unit-5x`) with a 24px icon frame (`--cc-icon-md`). The 20px circle inside it is Material `radio_button_checked` / `radio_button_unchecked`.
- **Colours:**

  | | Enabled | Hovered | Pressed | Disabled |
  |---|---|---|---|---|
  | Selected | `Accent/light` | `Accent/main` | `Accent/main`, opacity 0.7 | `Border/medium-contrast`, opacity 0.4 |
  | Not selected | `Border/medium-contrast` | `Border/low-contrast` | `Border/low-contrast`, opacity 0.7 | `Border/medium-contrast`, opacity 0.4 |

- **Focused:** a 24px circle with a 2px outside stroke in `Border/focus`.

### Behaviour (the WAI-ARIA radio group pattern)

- The group has `role="radiogroup"` and is named with `aria-label`. Each option has `role="radio"` with `aria-checked`, and is named by its text or `aria-label`.
- The group is one Tab stop. Tab lands on the checked radio, or on the first enabled one if none is checked.
- Arrow keys move and select, wrapping around and skipping disabled radios. Space selects the focused radio. Clicking the circle or the label selects.
- The group fires `input` and `change` once per user selection, after its `value` is updated.
- In a `<form>`, the group submits `name=value`, and resets to its initial `value` attribute.
- A disabled radio can't be selected, its click listeners don't fire, and it is announced as disabled.

## Steps taken

1. **Read Figma** (read-only `use_figma`): the set's variants, bound variables, and the focus-ring ellipse.
2. **Chose the structure.** The group is the form-associated element and owns `name`, `value`, the roving tabindex and the keyboard. The radios are options.
   - **Departure from the house convention:** the radio host carries `role="radio"` instead of wrapping a native `<input type=radio>`. Native radios in separate shadow roots can't form one group, because grouping by `name` works per tree. Each radio would then be its own group, with no arrow keys between them and a Tab stop on every radio. So the group would have to override all of the native behaviour anyway. For the same reason there is no `delegatesFocus` or `click()` forwarding: the host itself is the focusable element, and the native `click()` already reaches the group.
   - `role`, `aria-checked` and `aria-disabled` are host attributes rather than `ElementInternals` ARIA, so the Playwright locators used in tests can see them.
3. **Wrote `cc-radio.ts`:**
   - Attributes: `value` (default `on`, like a native radio), `checked` (set by the group, reflected for styling) and `disabled`.
   - Styling uses the checkbox's `--_color` / `--_color-hover` layer. The focus ring is a `::after` circle on the icon with a 2px outline. Without the font loaded, `clip-path` keeps the ligature text from spilling, as in the checkbox.
   - A host click guard blocks listeners when disabled, as in `cc-button`.
4. **Wrote `cc-radio-group.ts`:**
   - `formAssociated`. `setFormValue(value || null)` runs in `updated()`, and `formResetCallback` restores the `value` attribute.
   - Click and keydown are delegated from the group.
   - A `MutationObserver` (child list, plus `disabled` attributes) re-syncs `checked` and `tabindex` when radios are added or disabled later.
   - It re-exports `CcRadio`, so one import registers both elements.
5. **Stories:** Default, NoneSelected, WithDisabledOption, and AllVariants (selected/not selected × enabled/disabled, as in Figma).
6. **Tests:** `cc-radio.test.ts`, 19 tests:
   - value ↔ checked, both ways;
   - roles, names and states;
   - click, label click, and a single `change` already updated when it fires;
   - Tab lands on the checked radio, or the first enabled one;
   - arrow keys with wrapping and disabled skipping, and Space;
   - radios added later;
   - disabled: no selection, listeners blocked, announced;
   - form submit and reset;
   - Figma colours including hover, the disabled grey, 40/24 sizes, no ligature in the name, and the focus ring.
7. **Registered:**
   - `src/index.ts`, `exports` (`./radio.js` → `cc-radio-group.js`, which registers both) and the README.
   - Restored `cc-link`'s `index.ts` line, `./link.js` export and README row. They were missing from the link commit.

## Left out

- **Group `disabled`, `required` validation, and `formDisabledCallback`** (a disabled `<fieldset>`). The checkbox doesn't have these yet either. They belong in the shared form-control controller the plan describes.
- **A visible group label.** Figma has none; use `aria-label`.
- **`checked` on `<cc-radio>` in markup:** the group's `value` decides; `checked` is set by the group.
- **A horizontal layout option:** the group stacks vertically. Add `orientation` when a design needs it.
- **Right-to-left arrow mapping:** Right always moves forward.

## Designer questions

- **Disabled + selected is grey** (`Border/medium-contrast`) in the radio, but the checkbox keeps `Accent/light` when disabled and checked. I followed each Figma set as drawn. Which one is intended?
- **Hover on a selected control:** the radio uses `Accent/main`, the checkbox uses `Accent/dark`. Intended?
