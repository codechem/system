# List item

**Date:** 2026-11-10
**Changes:** uncommitted in the working tree.

## Goal

Build `<cc-list-item>` from the Figma "List Item" component set (file `K7Z7bb2IjqiyDjik5qjEoN`, set `378:2208`). The linked node `378:2233` is the documentation frame ("List Item"). The same page holds a second set, "Status priority" (`378:2203`, three coloured dots); it is not used by List Item and is out of scope. The plan (Wave B) says: "clarify whether lists are static, selectable, or navigational; each implies different ARIA".

## Requirements

### From Figma

- **Properties:** `State` (Enabled, Hovered, Pressed) and `Leading Icon` (Checkbox, Icon, No Icon); booleans Show leading icon (on), Show Smaller text (off), Show trailing icon (on); text properties Text, Supporting text. The documentation frame also shows a "Selected" column (checkbox checked, no fill).
- **Layout** (all rows 260px wide, radius `radius` 4px, content row 28px high):

| Leading | Height | Padding (t/r/b/l) | Gap | Leading element |
|---|---|---|---|---|
| Checkbox | 40 | 4 / 4 / 4 / 4 | `gap-0-25` (2) | `cc-checkbox` medium, 32px |
| Icon | 44 | 8 / 8 / 8 / 8 | `gap-1` (8) | `person_2`, `icon-sm` (20px), `Text/medium-emphasis` |
| No icon | 36 | 4 / 4 / 4 / 12 | `gap-0-5` (4) | none |

- **Text:** `Body text/small` (14/20, regular) in `Text/high-emphasis`; supporting text `Body text/extra small` (12/16) in `Text/low-emphasis`, stacked under the label.
- **Trailing:** a 28×28 icon button (padding 4, radius 4) with a 20px `close` icon in `Text/low-emphasis`.
- **States:**
  - Hovered: fill `Surface/surface-highlight-transparent` on the row.
  - Pressed: the same fill and the whole row at opacity 0.7.

### Behaviour

- The row is a list item (`role="listitem"`).
- With a leading checkbox, the checkbox is named by the label, toggles on click or Space, and a click anywhere on the row toggles it.
- The trailing button announces "Remove <label>" and fires `remove`.

## Steps taken

1. **Read Figma** (read-only `use_figma`): every variant with bound variables, the icon colours, and the screenshot as the visual target.
2. **API:** `<cc-list-item label supporting-text leading="checkbox|icon|none" icon selected hide-remove-button>`.
   - **`label`, `supporting-text` as attributes:** Figma's text properties. Supporting text is rendered only when set, which covers "Show Smaller text".
   - **`leading` and `icon`:** Figma's "Leading Icon" variant. `icon` is a Material icon name (default `person_2`). The default is `none` (Figma's default is Checkbox, but a bare item with a checkbox is surprising).
   - **`selected`:** the "Selected" column of the frame. Reflected, mirrored to the nested checkbox.
   - **`hide-remove-button`:** "Show trailing icon" is on by default in Figma, so it becomes an off switch, like `hide-info-icon` on the text area.
3. **Composition:** the leading checkbox is the existing `<cc-checkbox>` and the trailing button is `<cc-button icon-only variant="text" color="secondary" size="small">` with a `close` Material icon. The first version used a native `<button>` because `cc-button` had no icon-only style; it was switched afterwards, see [the icon-only button write-up](2026-11-10-icon-only-button.md). The icon colour is set through `::part(button)` to `Text/low-emphasis`, as Figma overrides it inside the list item.
4. **Styles:** tokens only. Padding, gap and leading column come from `--_py`, `--_pl`, `--_gap` switched per `leading` on `:host`. The row is `display: block` and fills its container (260px in Figma is the design width, not a fixed size). Pressed is `:active` with opacity 0.7, except while the remove button itself is pressed (`:has(.remove:active)`).
5. **Behaviour:** `ElementInternals.role = 'listitem'`; row click forwards to the checkbox unless the target is the checkbox or the remove button; `change` is re-dispatched from the host (the checkbox's `change` isn't composed); `remove` bubbles and is composed.
6. **Stories:** Default, WithCheckbox, Selected, WithIcon, WithSupportingText, AllVariants.
7. **Tests:** `cc-list-item.test.ts`, 25 tests.
8. **Registered** in `src/index.ts`, the `exports` (`./list-item.js`) and the README.

## Verification

- `tsc` is clean, `vitest` passes 164/164 (25 for the list item), `npm run build` succeeds.
- **Storybook against the Figma screenshot:** the three leading variants, the selected checkbox, supporting text, the close button, the hover fill and the Tab focus ring on the checkbox match.
- **Pressed** is checked in the tests with a real mouse press through CDP `Input.dispatchMouseEvent`.

## Left out

- **Disabled:** Figma defines no disabled state, so there is none (see designer questions).
- **Navigational items (`href`) and click events on the row:** Figma shows no link or button affordance on the row itself.
- **`role="list"` container:** the item sets `role="listitem"`; the consumer must wrap items in a `role="list"` element (a `<cc-list>` is not in the inventory).
- **Form participation:** the nested checkbox lives inside the item's shadow root, so it doesn't submit with an outer `<form>`. Use `selected` and `change`.
- **Localised "Remove" label:** the button name is English only, "Remove <label>".
- **`custom-elements.json`, axe checks, visual snapshot, Code Connect, changeset:** Definition of Done items for the whole library, not done here (same as the other components).

## Designer questions

- **What is the list for?** Checkbox + close button suggests a selectable list of removable entries (like a multi-select with chips). If items should also be navigational or single-select, the row needs `role="option"`/links and a different leading control.
- **Disabled state:** none designed. Should disabled items exist (dimmed 0.4, no events)?
- **Pressed on a non-interactive item:** with `leading` icon or none, the row isn't clickable, yet Figma dims it when pressed. Hover and pressed styles are applied to all rows as designed.
- **Hover fill:** the paint already has 50% opacity and the variable is 50% too, so Figma renders ~25%. The code uses the variable once (50%), like the text area.
- **Remove button states:** the list item's frames only show the close button Enabled; it now uses the Icon Only hover and pressed states of the Icon Button.
- **Content gap 72:** the "Content" frame has a fixed gap of 72px between text and button; the code uses `space-between` with a minimum gap of 8px (`gap-1`). Is a minimum of 72px intended?

## Review

Reviewed with `superpowers:requesting-code-review` by a separate reviewer agent, in a scratch clone with throwaway probes (13 mutations, AX-tree reads).

**Verdict:** no Critical or Important issues; seven Minor findings, the cheap ones fixed.

**What the reviewer confirmed:** a row click toggles once (one `change`, one `input`), a direct checkbox click toggles once, Space toggles, Enter doesn't; `selected` syncs both ways and survives switching `leading` at runtime; `change` bubbles and is not composed, `remove` bubbles and fires on click, Enter and Space of the button without toggling the row; the AX tree shows `listitem`, `checkbox "<label>"` and `button "Remove <label>"` with no icon glyphs in names; tokens only, `--_*` variables, `:host([hidden])`, JSDoc only, guarded `define`; registration is correct. 10 of 13 mutations were caught by the tests.

| Severity | Finding | Fix or reason left |
|---|---|---|
| Minor | Two weak tests: removing `aria-hidden` from the icons survived (the button's `aria-label` overrides content, so the old test could never fail); `composed: true` on `remove` survived | Added a test asserting `aria-hidden` on both icons; removed `composed` (the event is dispatched on the host, so it was dead) |
| Minor | Empty `label` gives an unnamed checkbox | JSDoc on `label`: it names the checkbox and the remove button, so set it |
| Minor | No pointer cursor on a row that toggles a checkbox | `cursor: pointer` on the row with `leading="checkbox"`; test |
| Minor | A row click dispatches a second host `click` (the forwarded `cc-checkbox.click()`); a direct checkbox click also logs two | Left: native label behaviour, the same in `cc-checkbox` alone; follows from the chosen design |
| Minor | No `delegatesFocus` | Left on purpose: the item has two focus targets (checkbox, remove button) and no single inner target. With `delegatesFocus`, clicking the text of a row without a checkbox would focus the remove button. Tab order works |
| Minor | Double dim on a checkbox row (the row at 0.7 and the nested checkbox box at 0.7 on `:active`) | Left: unchecked against Figma; added to the designer questions below |
| Minor | `role="listitem"` without a `<cc-list>` | Already under Left out; the container needs `role="list"` |

**Declined by the reviewer:** screen readers, pixel match (72px gap, hover opacity), axe, visual snapshot, Code Connect, changeset, `custom-elements.json`, Firefox and WebKit, the HTML/React sandboxes, the stories.

**After the fixes:** `tsc` is clean, `vitest` passes 181/181 (29 for the list item, 24 for the button after the icon-only change), and `npm run build` succeeds.
