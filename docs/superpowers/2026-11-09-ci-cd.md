# CI/CD: test and publish with GitHub Actions

**Date:** 2026-11-09
**Base:** `aa67e98`. Changes are uncommitted in the working tree. Not run on GitHub yet.

> Historical implementation record. The current workflow is `.github/workflows/release.yml`; see README for current setup. As of 2026-11-11, stable versions explicitly publish to `latest` and prereleases to `next`. The prerelease limitation recorded below no longer applies.

## Goal

A GitHub Actions workflow that tests every change and publishes `@codechem/tokens` and `@codechem/components` to npm.

## Requirements

- Tests run on pushes to `main` and on pull requests.
- Publishing happens only on purpose, never on an ordinary push.
- CI uses the same Node and npm as local development (Node from `.nvmrc`, npm 12).
- Nothing publishes unless the tests pass.
- No version bump commits are needed to release.

## Steps taken

1. Added `.github/workflows/ci.yml` with two jobs:
   - **test** (on push to `main`, pull requests and `v*` tags):
     1. Set up Node from `.nvmrc` with the npm cache, then upgrade to npm 12.
     2. `npm ci`.
     3. Install Chromium with its system libraries (`--with-deps`).
     4. `npm run build`, then `npm test`.
   - **publish** (only on `v*` tags, after **test** passes):
     1. Set the version of both packages from the tag, so `v0.1.0` becomes `0.1.0`. This uses `npm version --no-git-tag-version`, which changes the files on the runner only.
     2. Build.
     3. `npm publish --access public --provenance` for both packages.
2. Chose lock-step versions: one tag releases both packages with the same version. That's the simplest way to go while the components and tokens change together.
3. Authentication:
   - `NODE_AUTH_TOKEN` comes from the `NPM_TOKEN` repository secret.
   - `id-token: write` lets npm attach a provenance statement. It also allows npm trusted publishing (OIDC), which can replace the token later.

## How to release (once set up)

1. Make sure the `codechem` org exists on npmjs.com and that you can publish to it.
2. Create a granular access token with write access to the `@codechem` scope:
   - Tick **Bypass two-factor authentication**, or CI fails with EOTP.
   - Note the expiry date; write tokens last at most 90 days.
3. Add the token as the repository secret `NPM_TOKEN`.
4. Run `git tag v0.1.0 && git push origin v0.1.0`. Use plain release versions only: a prerelease such as `v1.0.0-beta.1` would still be published as `latest`.
5. After the first release, set up a trusted publisher on npmjs.com for `codechem/system` with workflow `ci.yml`, then delete the token. The workflow already has `id-token: write`, and npm 12 tries OIDC first.

If a release fails after one package was published, re-running the job fails on that package, because npm never accepts the same version twice. Push a new patch tag instead.
