# Build with CodeChem

Install the components, connect your application state, and build an interface that shares CodeChem’s design language. These are standard custom elements built with Lit—not React wrappers—so the same tags work across frameworks.

## Install

Use a modern browser and a bundler such as Vite. Start in an existing application:

```sh
npm install @codechem/components
```

| Package | What you get |
|---|---|
| `@codechem/components` | Registered `cc-*` elements, TypeScript declarations, bundled fonts and editor metadata |
| `@codechem/tokens` | CSS custom properties for color, spacing and typography; installed with the components |

Import only the components you use from your application’s browser entry point:

```js
import '@codechem/components/text-input.js';
import '@codechem/components/checkbox.js';
import '@codechem/components/button.js';
```

For exploration, `import '@codechem/components'` registers the whole library. Per-component imports make your dependencies explicit. Importing a component also loads the design tokens, Kumbh Sans and Material Icons Round; you do not need a Google Fonts request.

## Make your first form

Add this markup to your page. Custom elements need closing tags, even when they have no content.

```html
<form id="project-form">
  <cc-text-input label="Project name" name="project" required></cc-text-input>
  <cc-checkbox name="updates" value="email" checked>
    Email me project updates
  </cc-checkbox>
  <cc-button type="submit">Create project</cc-button>
</form>
<p id="project-result" role="status"></p>
```

Attach the listener after the markup exists. Named form-associated controls participate in native validation and `FormData`:

```js
const form = document.querySelector('#project-form');
const result = document.querySelector('#project-result');

form.addEventListener('submit', (event) => {
  event.preventDefault();
  const data = new FormData(form);
  result.textContent = `Created project: ${data.get('project')}`;
  // Send data to your API here. Never inject form values with innerHTML.
});
```

The button defaults to `type="button"`, so the explicit submit type matters. Unchecked checkboxes do not add a form entry. See [Forms and events](?path=/docs/guides-forms-and-events--docs) for state updates, validation and component-specific exceptions.

## Match your application

The shipped tokens define a **dark theme**. Use the token surfaces behind the components; placing them on a white canvas does not create a light theme.

```css
@import '@codechem/tokens/tokens.css' layer(cc-tokens);

body {
  margin: 0;
  background: var(--cc-background);
  color: var(--cc-text-high-emphasis);
  font-family: var(--cc-typeface-typeface);
}
```

The explicit stylesheet import can establish the page background before JavaScript runs. [Styling and theming](?path=/docs/guides-styling-and-theming--docs) explains scoped overrides, shadow DOM and CSS parts.

## Framework setup

Use the [Framework integration guide](?path=/docs/guides-framework-integration--docs) for React, Vue, Angular, Lit and server-rendered applications. Framework configuration differs; a custom element is not automatically a framework-controlled input.

## Editor support

For HTML completions in VS Code, add this to `.vscode/settings.json`:

```json
{
  "html.customData": [
    "./node_modules/@codechem/components/vscode.html-custom-data.json"
  ]
}
```

TypeScript types are included in each package entry. A Custom Elements Manifest is available at `@codechem/components/custom-elements.json` for other editor integrations.

## If something looks wrong

- **The tag renders nothing:** verify its browser-side import ran. Check `customElements.get('cc-button')` in DevTools.
- **A boolean will not turn off:** `disabled="false"` still enables a boolean attribute. Remove it or set the property to `false`.
- **State looks stale:** read the element’s live property (`value`, `checked`, `page`), not its original HTML attribute.
- **Styles do not reach the input:** the inner control lives in shadow DOM. Use documented tokens or CSS parts, not descendant selectors.
- **An import is missing:** check the exports of your installed package version; the repository may be ahead of npm.
